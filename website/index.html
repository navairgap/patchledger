OverviewOne ledger for every scanner

Developers run one tool for secrets, another for vulnerable dependencies, a third for insecure code. PatchLedger imports their results — or runs them for you — and merges everything into a single, deduplicated, scored, and explainable ledger that persists across scans.

⇉

Bring SARIF, semgrep, gitleaks, bandit, and pip-audit reports — or let PatchLedger run the tools it finds on your machine.

The problemTool sprawl, manual triage, unverifiable fixes

⌗

Five tools, five formats

Severity scales differ, paths differ, duplicates multiply. Triaging means juggling five dashboards and a spreadsheet.

?

"Is it fixed?" is a guess

Most pipelines call a finding resolved when it stops appearing — even if the scanner never ran, crashed, or didn't cover that code.

⏳

No memory between scans

Without scan history you can't tell "persistent since March" from "new this week" — or catch a fix silently regressing.

PatchLedger's answer: a local-first ledger with deterministic fingerprints, explainable risk scores, and patch verification that refuses to claim a fix without evidence. No cloud account, no AI subscription, no data leaving your machine.

FeaturesBuilt for real remediation work

Honest scan coverage

Every scan records which tools ran, failed, or were missing. Reports are labelled incomplete when coverage isn't full — never silently optimistic.

Stable fingerprints

Findings survive line shifts and formatter runs; genuinely changed code gets a new identity. Fingerprints are versioned and documented.

Explainable risk scores

Deterministic 0–100 scores where every adjustment is listed: severity base, confidence, evidence quality, category.

Scan history & diffs

Compare any two scans: new, persistent, reintroduced, changed severity, changed location — with an audit trail of status transitions.

Local remediation knowledge

Offline guidance per rule category: why it matters, consequences, concrete fix, secure pattern, references. Advice stays separate from evidence.

Offline AI review prompts

Generate a reviewer-ready Markdown prompt from selected findings — with explicit rules against inventing evidence. Bring your own reviewer, human or AI.

Secret redaction

Leaked credentials are redacted on ingest (gitleaks matches, PEM blocks, common token formats) before anything is stored or rendered.

CI-ready exit codes

--fail-on high exits 2 on threshold hits; --strict exits 3 on incomplete scans. Documented and GitHub-Actions ready.

How it worksFrom raw scanners to verified fixes

  1. Scan or importRun available scanners against your repo, or import existing reports. Tools that are missing are recorded, not hidden.
  2. NormalizeEvery result becomes one finding model: normalized severity, confidence, category, evidence, remediation guidance — scanner metadata preserved verbatim.
  3. Fingerprint & dedupDeterministic sha256 fingerprints merge duplicate sightings while keeping every occurrence's evidence distinct and intact.
  4. Score & storeExplainable risk scores are attached; the scan is committed to your local SQLite ledger as an immutable observation point.
  5. Compare & verifyThe next scan is diffed against history. Disappeared findings become resolution candidates — verified fixed only with real scanner coverage.
  6. ReportGenerate JSON, Markdown, or single-file HTML reports — with coverage honesty and verification status baked in.

Security scanningRun what you have — honestly

PatchLedger runs the scanners it finds on your machine and records the status of each one. A missing tool is a fact, not a failure: your scan is labelled incomplete and no resolution claims are made on top of it.

No downloads, no surprises: PatchLedger never fetches or executes scanner binaries on its own. It only invokes tools already installed on your system — patchledger doctor tells you what it can see.

Finding normalizationOne consistent data model

Every scanner's raw result is mapped through explicit, documented tables — severity is never invented, unknown values stay unknown, and each finding keeps its original scanner metadata alongside the normalized view.

Explicit severity mapping

semgrep ERROR, bandit HIGH, SARIF error — all map to one scale, with the raw value preserved for audit.

Content-stable fingerprints

sha256(scanner, rule, path, message, snippet) — stable across line shifts, versioned as fp2, documented with its limits.

Dedup with receipts

Identical findings merge into one ledger entry; every merged sighting stays listed as an occurrence with its own evidence.

Secrets redacted on ingest

gitleaks matches, PEM blocks, and common token formats are redacted before storage. The fix is still rotation — redaction just stops re-leaking.

Patch verificationNever call it fixed without proof

After you change code and rescan, a vanished finding is only a resolution candidate. PatchLedger verifies the candidate against the evidence: did every scanner that ever reported this finding actually run, succeed, and cover the same target? Only then is it fixed and verified.

fixed_verified still_present reintroduced inconclusive

Missing scanner ⇒ inconclusive

semgrep reported it last time but didn't run now? Inconclusive. The finding stays effectively open, with the reason recorded.

Failed scan ⇒ inconclusive

A scanner that exited with errors cannot confirm absence. Verification refuses to inherit someone else's crash as your fix.

Imported reports ⇒ inconclusive

Imported results can't assert local coverage. Verification against them stays inconclusive by design — documented, not hidden.

Everything ran ⇒ verified

All reporting scanners succeeded on the same target? The finding is marked resolved with the evidence trail attached. Version changes are recorded as caveats.

Why this matters: false "resolved" states are how regressions slip into production. An honest inconclusive costs a re-run; a false fixed costs a breach.

ArchitectureModular, local-first, boring on purpose

Python 3.10+, Typer CLI, Pydantic models, SQLite storage, Rich terminal output. No server required, no telemetry, no network after installation.

Immutable scans

Each scan is an observation point; history is a query across scans plus an explicit status audit trail.

Versioned everything

Schema migrations and fingerprint versions are part of the design — the ledger stays maintainable.

Security-product hygiene

Argv-list subprocesses, no shell, no auto-downloads, escaped HTML with CSP, path validation, no secrets in output.

InstallationUp and running in two minutes

1 · Install PatchLedger

$ pipx install patchledger
# or: pip install patchledger
# dev: git clone + pip install -e .[dev]

2 · Check your scanners

$ patchledger doctor
# install any you want: pip install bandit pip-audit
# semgrep: pip install semgrep · gitleaks/trivy: system pkg

3 · Scan your repo

$ cd your-project
$ patchledger init
$ patchledger scan .
$ patchledger findings

4 · Verify a fix

$ # ...fix the code...
$ patchledger scan .
$ patchledger verify
$ patchledger report --format html
Requires: Python 3.10+. Everything else is optional — PatchLedger degrades gracefully and tells you exactly what coverage you have.
