# FAQ

## Does PatchLedger need an AI API?

No. The core engine — scanning, normalization, deduplication, scoring,
comparison, verification, reporting — is fully deterministic and works
offline. `patchledger export-ai` generates a structured review prompt you can
paste into *any* external assistant or hand to a human reviewer; the prompt
carries the evidence and forbids inventing more. A bring-your-own-key AI
integration may arrive later as an optional extension — it will never be
required.

## Where does my code go?

Nowhere. Scanning runs locally against your working tree. The only outbound
network use is pip-audit querying the PyPI advisory database. Reports are
written where you point them (and uploaded as CI artifacts only if you
configure that).

## A scanner disappeared between scans — is that finding "fixed"?

No — it is *inconclusive*. PatchLedger only marks a finding resolved when
every scanner that ever reported it ran successfully in the newer scan on the
same target. Missing tools, failed scans, and imported reports all produce
inconclusive verdicts with recorded reasons. Run the missing scanner and
rescan to turn inconclusive into verified.

## Why did my finding's fingerprint change after I edited the flagged line?

By design: the fingerprint includes the code snippet, and the snippet changed.
The old finding becomes a resolution candidate (verified fixed if coverage
was sufficient) and the edited line appears as a new finding. Edits elsewhere
in the file do *not* change the fingerprint.

## Can two different scanners' findings be merged?

No. Fingerprints include the scanner identity, so semgrep and bandit sightings
of the same problem stay separate findings — merging them would lose the
per-tool evidence that patch verification depends on.

## How do I silence a rule?

Only via explicit configuration: put the rule id in
`.patchledger/config.json` under `import_config.disabled_rules`. Suppression
is never silent — the scan/import output reports exactly what was suppressed
and how often.

## Are example reports real scan data?

No. Everything under `examples/` and the website's report preview is
synthetic, clearly labelled, and generated by `scripts/generate_examples.py`
from fabricated findings.

## Is the HTML report safe to share?

It is a single self-contained file with no JavaScript and a restrictive CSP;
all dynamic content is escaped. It does contain your findings — including
redacted evidence — so treat it as sensitive and share it deliberately.

## Does it run on Windows/macOS?

The package targets any OS with Python 3.10+ (console scripts, no compiled
deps). Most testing happens on Linux; scanner availability varies per OS the
same way it would for the scanners themselves. Windows-specific issues are
welcome bug reports.

## How is this different from just running the scanners?

Running the scanners gives you five report formats, five severity scales, no
history, and no proof. PatchLedger gives you one ledger with stable identity
across time, explainable scores, and — the point — verification that a fix
actually happened before anyone marks it done.
